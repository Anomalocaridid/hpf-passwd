# Contributing to hpf-passwd

Thank you for considering contributing to hpf-passwd!

If you believe that this file is missing relevant information or is otherwise unclear, please feel free to make an issue or pull request.

## Development Guide

### Prerequisites
  - [nix](https://nixos.org/)

This project relies on using nix-specific tools, namely [nixos-option](https://search.nixos.org/packages?channel=unstable&query=nixos-option#show=nixos-option), and so installing development dependencies using nix is the only supported method.

This project supports using nix with and without flake support enabled.
(i.e. Whether or not `experimental-features = flakes` is set is nix settings.)

### Guidelines
  - Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) to format commit messages.
  - If adding a new feature or otherwise significantly changing behavior, please add regression tests.
  - If adding tests that rely on running nix either directly or by running a program that runs nix, they must be skipped when the tests are run as part of the nix package's build process. To do this, annotate them with `# @tag runs_nix` like so:
    ```bash 
    # @tag runs_nix
    function test_example() {
      # Do some testing
    }
    ```
  - Please try to minimize tests that require being skipped like this and prefer using `bashunit::mock` to imitate them instead.

### Example Workflow

Note, the steps shown below are mainly for illustrative purposes.

  1. Clone and enter git repository
  1. If using nix with flakes enabled, run `nix develop`, otherwise run `nix-shell`
  1. Make and test changes
  1. Add or modify tests if applicable
  1. Test changes for regressions with `bashunit test`
  1. Test building nix package with `nix build`
  1. Make further changes and repeat steps as necessary
  1. Create pull request

## AI-generated Contributions

Contributions must not include any content generated by large language models or any other probabilistic tools.

This includes, but is not limited to, code, documentation, assets, commit messages, and issue/PR/discussion text.

Any issues or PRs containing such content may be closed without further consideration.

Adding dependencies that contain AI-generated content is discouraged and should be avoided when feasible.

For explanation as to why, see [Why not LLMs?](https://codeberg.org/small-hack/open-slopware#why-not-llms)
